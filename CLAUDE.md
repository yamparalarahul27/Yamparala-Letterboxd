# Project rules

## Per-file line cap: **700**

Every file in this repo is capped at **700 effective lines** (blank lines and comment-only lines don't count). This applies across the board — source code, data, styles, docs, workflows. The intent is to keep any single file scannable in a diff or on a phone, and to force natural splits when content grows.

### Enforcement

Two checks, both in `npm run check`:

1. **`npm run lint`** — ESLint's `max-lines` rule covers `.ts`, `.tsx`, `.mjs`, `.js` (configured in `eslint.config.mjs`).
2. **`npm run check:lines`** — `scripts/check-lines.mjs` covers `.json`, `.css`, `.md`, `.yml`/`.yaml` files.

CI (`.github/workflows/ci.yml`) runs both on every PR and push to `main`, plus `npm run typecheck` and the production build. A file over the cap fails the build.

### Exemptions

- `node_modules/`, `.next/`, `out/`, `build/`, `.git/` — generated or external.
- `.agent/`, `.agents/` — vendored agent skill packs (third-party documentation).
- `package-lock.json` — generated by npm.

### When you hit the cap

Don't bypass — split. Natural split patterns we use:

- **Data by type** — `data/parts/` is split into `tips.json`, `wheels.json`, `rings.json`, `tracks.json`.
- **Data by series** — `data/beyblades/` is split into `{metal-fusion,metal-masters,metal-fury}.json`; `data/watchlist/` into `{anime,movies,series}.json`.
- **Code by responsibility** — extract helper components into `components/ui/`, extract design constants into `data/design-tokens.ts`, etc.
- **Pages by section** — if a page grows large, extract sections into co-located components (e.g. `app/foo/_components/Hero.tsx`).

The cap is a forcing function for organization, not a hard ceiling. If a split would feel artificial, find a different one.

## Other notes

- All routes are statically pre-rendered (`generateStaticParams` for dynamic ones). Don't introduce runtime data fetching unless we agree first.
- Editorial fields (Beyblade `stats.*` and `description`; Character `bio`, `role`, `team`; Part `info`) are hand-curated and **must not be overwritten by sync**. Sync only touches canonical fields and lead images.
